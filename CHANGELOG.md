# Changelog

All notable changes to macguffin are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

GitHub release notes are generated by goreleaser from commit messages; this file
is the curated, human-readable summary kept in sync at each release cut.

`mg` carries no version constant in source: `main.version` is the `dev` sentinel
until goreleaser stamps the tag in via `-ldflags -X main.version={{.Version}}`.
The tag *is* the version bump; this file is the prep artifact that accompanies it.

## [Unreleased]

### Added

- **Workspace isolation: `--root` flag and `MG_ROOT` env var (mg-4fa7).** The
  store is now resolved as `--root` > `$MG_ROOT` > `$HOME/.macguffin`. Previously
  the root was unconditionally `$HOME/.macguffin`, and the only way to point `mg`
  at a scratch store was to override `$HOME` — which relocates every other tool's
  config too. Because `mg` never walks up from `$PWD`, `cd` gave *zero* isolation:
  a smoke script that ran `mg init/new/claim/done` inside a scratch directory hit
  the **real** store, and `mg list --json | head -1` handed it a live work item,
  which it then marked done. `mg event` and `mg log` pass their arguments through
  verbatim and so bind only `$MG_ROOT`, not `--root`. See "Workspace root" in the
  README.

### Fixed

- **Silent data loss on short-ID collision (mg-38b9).** `mg new` wrote work items
  with `os.WriteFile`, which *truncates*. A new item whose 4-hex-digit ID collided
  with a live item in `available/` or `pending/` destroyed that item, silently and
  without a trace (~1 in 4096 per mint). Items are now created with
  `O_CREATE|O_EXCL`, and a candidate ID that already names an item **anywhere** in
  the store — including `archive/` and `shelved/`, which `O_EXCL` on one directory
  never sees — is reminted before use. Because the ID is a deterministic hash of
  (title, created) rather than a random draw, the remint mixes a nonce into the
  hash input; a retry loop that did not would re-derive the same ID forever.

### Changed

- **Ambiguous short IDs now error instead of silently resolving to one item
  (mg-38b9).** Seven commands (`show`, `edit`, `claim`, `done`, `unclaim`,
  `reopen`, `shelve`/`unshelve`/`unarchive`) each walked the store independently
  and took the first filesystem hit, so a duplicated ID resolved to whichever
  directory was scanned first — and `mg show` could render one item's body under
  another item's status. They now share one `workitem.Resolve`, which returns
  *every* match. Two or more is a new `ambiguous_id` conflict error (exit 4)
  listing each candidate path. Existing duplicate IDs are **not** renumbered:
  the commit trailers, audit-log lines and roadmap links pointing at them stay
  valid, and the ambiguity is reported at read time rather than papered over.

- **A short ID shared by one live item and an archived record now resolves to
  the live item, loudly (mg-fb07).** Ambiguity is only ambiguity among
  candidates of the same *terminality*: a live work item
  (`available`/`claimed`/`pending`/`shelved`) and a historical record
  (`done`/`archived`) are not two equally plausible answers to "what is
  `mg-4fa7`". Exactly one live candidate wins and mg prints a note to **stderr**
  naming the shadowed record's exact path — strictly more information than
  either the pre-mg-38b9 silent wrong answer or a bare error. Two live
  candidates, or two terminal ones, remain an `ambiguous_id` error. The note
  goes to stderr precisely so it never corrupts the `--json` contract on stdout.

## [0.2.0] - 2026-07-10

Minor release rolling up the 30 commits merged since v0.1.4 (this release-prep
commit excluded).

**Semver rationale:** a minor (0.2.0) rather than a patch bump because this adds
new backwards-compatible capabilities — `--json` on the query commands, `mg schema`,
`mg --version`, mail threading and `mg mail reply`, mail audit logging, and
`mg spend` calendar windows — alongside three security fixes to mail handling.
Nothing breaks for an existing install. The one change that *could* have broken a
consumer is the typed-error taxonomy: `mg` now exits 2/3/4 for usage, not-found
and conflict errors where every error used to exit 1. Exit 0 still means success
and every failure is still non-zero, so a consumer that tests success-vs-failure
(as pogo does — it reads `exec.Command` errors, never the specific code) is
unaffected. Only a consumer matching on the literal `1` would notice, and none does.

### Added

#### Machine-readable output
- **`--json` on every query command, and `--help` stays safe on passthrough
  commands** (mg-9be5). `mg list`, `mg show`, `mg flow`, `mg spend` and every
  `mg mail` subcommand emit a structured object on stdout, so callers no longer
  scrape human prose. The mutating commands (`new`, `claim`, `done`, `edit`,
  `assign`, `reopen`, …) still report in prose and are unchanged.
- **`mg schema` dumps the command tree as JSON** (mg-7fd0). Includes a
  `schema_version` field and per-command `idempotent` hints, both documented as
  advisory rather than contractual (`mg edit` is marked `idempotent=false`).
- **`mg --version` / `-v`, matching the `mg version` subcommand** (mg-7fd0).
  Release builds append commit and date build metadata, e.g.
  `mg v0.2.0 (abc1234, 2026-07-10)`; a plain `go build` still reports `dev`.
- **`mg flow --json` writes through `cmd.OutOrStdout()`** (mg-b093), making the
  flow output testable rather than bound to the process's stdout.

#### Mail
- **Mailbox enumeration and a first-delivery signal** (mg-89d7). `mg mail` with
  no arguments lists mailboxes; `mg mail --json` renders them structurally, and a
  send reports whether it created the recipient's mailbox (`mailbox_created`).
- **Correlation ids and threading** (mg-55f9). Every delivered message carries a
  `Message-Id` equal to its maildir file name — no new id space. `mg mail send
  --in-reply-to MSG-ID` is the raw primitive; `mg mail reply AGENT/MSG-ID` is the
  form that carries a full `References` ancestry forward. Messages without these
  headers behave exactly as before.
- **Mail-audit log and a cross-box read guard** (mg-6ae0). Reads and archives
  are recorded, and reading another agent's mailbox no longer silently marks its
  messages read.
- **`mg mail list --archived` inspects archived mail** (mg-3e13).
- **Mail lifecycle events, with malformed messages failing loudly** (mg-9696)
  rather than being skipped in silence.

#### Spend
- **`mg spend` gains named calendar windows and a summary total** (mg-8b6b): a
  grand-`TOTAL` row in the default table and a `total` object in `--json`.

#### Errors
- **`internal/mgerr`, a typed error taxonomy** (mg-931f), emitted and rendered
  across every `mg` command, with contract tests and `docs/error-taxonomy.md`.

### Changed

- **Error exit codes are now categorized** (mg-931f). `1` internal (unchanged
  catch-all), `2` usage, `3` not found, `4` conflict. Retryability is a field on
  the error, not a code — a race-lost claim and a hard conflict are both `4`.
- **Error messages on the state-transition commands are written for the person
  running the command** (mg-c835). `claim`, `done`, `unclaim`, `reopen`,
  `shelve`, `unshelve` — plus `Create`, `Update`, `Unarchive` and `mail send` —
  name the semantic problem (`mg-1234: no such work item.`) instead of surfacing
  a raw `rename(2)`/ENOENT, and no longer expose the maildir layout, the rename
  op, or the PID-suffix lock. `mg mail read` on a missing message id is outside
  that audit and still wraps the underlying `os.PathError`.
- **`--tags` is the canonical flag on both `mg new` and `mg edit`** (mg-7fd0),
  and `mg list --status` derives its usage text and its validation from a single
  canonical slice, so the two can no longer drift.

### Security

- **Mail path components can no longer traverse the maildir** (mg-ea5a).
  `mg mail read AGENT ../../../secret` read a file outside the mailbox, and
  `mg mail archive` *moved* it into `archive/`. Both are now usage errors
  (exit 2), rejected at every site that joins an untrusted component. Separately,
  a message is never overwritten when a `msgID` collides — the id is re-minted.
- **Control characters are rejected in mail path components** (mg-21a6), closing
  an audit-log forgery. The audit log is newline-delimited, so a recipient name
  containing a newline terminated its own record and appended a second,
  fully attacker-controlled one. Every C0 control and DEL is now refused.
- **Mail header values reject CR, LF and every other control character**
  (mg-55f9). `mg mail send --subject=$'pwned\nIn-Reply-To: x'` previously wrote
  the injected header and exited 0; it is now `CatUsage` / exit 2. Validation
  runs before any filesystem work, so a rejected send leaves no message, no tmp
  file, and no lazily-created mailbox.

- `docs/error-taxonomy.md` (mg-931f) and `docs/error-message-audit.md` (mg-c835).
